Firebase Authentication＋Firestore 跨裝置同步設定步驟

本版用途
========
同一位使用者以相同帳號登入後，可在 iPhone、iPad 與電腦同步：
1. 已作答題目
2. 答對與答錯次數
3. 略過題目與略過次數
4. 收藏狀態
5. 最後一次作答狀態
6. 目前練習位置

未登入時仍可使用，紀錄只保存在目前裝置。
Firebase 設定完成後，GitHub Pages 網頁才能啟用登入及雲端同步。

注意
====
本套件固定載入 Firebase Web SDK 10.12.5，以避免日後最新版變動造成程式失效。
Firebase Console 的選單名稱可能因介面更新而略有不同。


一、建立 Firebase 專案
======================
1. 開啟：https://console.firebase.google.com/
2. 點選「建立專案」。
3. 輸入專案名稱，例如：
   procurement-quiz-sync
4. Google Analytics 可依需要選擇是否啟用。
5. 完成專案建立。


二、建立 Firebase Web 應用程式
=============================
1. 進入 Firebase 專案首頁。
2. 點選 Web 圖示「</>」。
3. 應用程式暱稱可填：
   procurement-quiz-web
4. 不需要勾選 Firebase Hosting，因為網頁仍部署在 GitHub Pages。
5. 完成後會看到 firebaseConfig，例如：

   const firebaseConfig = {
     apiKey: "...",
     authDomain: "...firebaseapp.com",
     projectId: "...",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "..."
   };

6. 開啟本套件中的：
   firebase-config.js

7. 將對應值貼入：

   window.FIREBASE_CONFIG = {
     apiKey: "你的值",
     authDomain: "你的值",
     projectId: "你的值",
     storageBucket: "你的值",
     messagingSenderId: "你的值",
     appId: "你的值"
   };

重要：
Firebase Web API Key 會出現在前端，這是 Firebase Web 架構的正常設計。
資料安全不是靠隱藏這組 Key，而是靠 Authentication 與 Firestore Rules。


三、啟用 Authentication
=======================
1. Firebase Console 左側選單進入：
   Build → Authentication
2. 點選「開始使用」。
3. 進入 Sign-in method／登入方式。
4. 啟用「電子郵件／密碼」。
5. 啟用「Google」登入：
   - 選擇專案支援電子郵件
   - 儲存

建議同時啟用兩種登入方式，方便使用者選擇。


四、加入 GitHub Pages 授權網域
=============================
假設題庫網址為：

https://abc123.github.io/procurement-quiz/

授權網域應填：

abc123.github.io

步驟：
1. Authentication → Settings／設定。
2. 找到 Authorized domains／授權網域。
3. 新增：
   你的帳號.github.io
4. 不要加入 https://
5. 不要加入 Repository 名稱。
6. 不要在最後加入斜線。


五、建立 Firestore Database
===========================
1. Firebase Console 左側進入：
   Build → Firestore Database
2. 點選「建立資料庫」。
3. 選擇適合使用者所在地的區域。
4. 建議先選「正式模式」或鎖定模式。
5. 建立完成後，進入 Rules／規則。


六、設定 Firestore 安全規則
===========================
1. 開啟本套件中的：
   firestore.rules
2. 複製全部內容。
3. 貼到 Firestore Database → Rules。
4. 按「發布」。

規則效果：
- 使用者必須登入。
- 使用者只能讀寫自己的 users/{uid} 資料。
- 不同使用者無法互相查看學習紀錄。
- 其他所有未授權路徑一律拒絕。

八、第一次登入與同步
====================
1. 開啟 GitHub Pages 題庫網址。
2. 點右上角「登入同步」。
3. 選擇：
   - Google 帳號登入
   - 電子郵件與密碼登入
4. 第一次登入時：
   - 如果雲端沒有紀錄，會將目前裝置的本機紀錄上傳。
   - 如果雲端已有紀錄，會依每一題 updatedAtMs 選擇較新的紀錄。
5. 同步完成後會顯示「已同步」。

換到另一台裝置：
1. 開啟同一 GitHub Pages 網址。
2. 登入同一帳號。
3. 系統會自動下載並合併學習歷程。


九、同步規則
============
1. 作答、略過及收藏後，先立即保存於 localStorage。
2. 已登入且有網路時，約一秒內自動上傳 Firestore。
3. 無網路時仍可作答，資料保留在本機。
4. 恢復網路、重新開啟頁面或回到前景時會再嘗試同步。
5. 同一題在不同裝置都有紀錄時，以 updatedAtMs 較新者為準。
6. 清除全部紀錄時：
   - 未登入：只清除本機。
   - 已登入：會同步刪除該帳號的雲端題目紀錄。


十、測試方式
============
測試裝置 A：
1. 登入帳號。
2. 作答一題、略過一題、收藏一題。
3. 確認顯示「已自動同步」。

測試裝置 B：
1. 開啟同一網址。
2. 登入相同帳號。
3. 點「立即同步」。
4. 確認作答、略過及收藏狀態一致。


十一、常見問題
==============
A. 顯示「尚未填入 Firebase 設定」
   檢查 firebase-config.js 是否仍有「請貼上」文字。

B. Google 登入顯示 unauthorized-domain
   將「你的帳號.github.io」加入 Authentication 授權網域。

C. 顯示 Missing or insufficient permissions
   Firestore Rules 尚未發布，或登入帳號與文件 userId 不一致。

D. iPhone 或 iPad 仍顯示舊版
   1. 網址後加 ?v=8
   2. Safari 重新整理
   3. 關閉主畫面 App 後重開
   4. 必要時刪除主畫面捷徑後重新加入

E. 本機 HTML 無法登入
   Firebase Authentication 需要 HTTP／HTTPS 網址。
   請部署至 GitHub Pages 後測試，不要以 file:// 直接測試雲端登入。

F. 同步大量舊紀錄需要較久
   第一次登入時可能上傳多筆已作答題目，請保持網路連線並等待完成。
